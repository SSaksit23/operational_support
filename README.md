# Operational support agent

A web app for the operations team of a Thai outbound tour company (2U Center / Go 365). An officer uploads one group's documents. The app reads them, cross-checks them, and prepares the tour leader's paperwork.

## What it does

- **Reads** the customer name list (xlsx), the preparation letter (pdf), e-tickets (pdf), the PNR record (docx), the Chinese land confirmation (团队确认件 or any `CFM …` file), the TL expense template (xlsx), and passport scans (photos, PDFs, or Word files of pasted scans; the machine-readable zone is read with local OCR).
- **Cross-checks** flights, dates, hotels, rooms, names, tickets, guide and land contacts, optional tours, and passport validity. Each mismatch is shown side by side with a "use this value" button, and you can download a corrected name list.
- **Internal check** tab (ops team only): passports × name list × preparation letter, one row per traveller (name, passport number, birth date, expiry, sex, and 6-month validity after the return date).
- **Drafts** the Thai TL assignment message (LINE) and re-checks it after edits.
- **Fills** the TL expense workbook, with a company selector for the header and tax block.
- **Saves** groups to PostgreSQL + pgvector (Neon) for search later. Passport and ID numbers are encrypted.

## Run locally

```
python -m venv .venv && .venv\Scripts\pip install -r requirements.txt   # or run-web.bat on Windows
uvicorn ops_agent.web.app:app --port 8000
```

Optional settings come from environment variables, or from `.env.ops` / `.env.local` next to the app:

| Variable | Purpose |
|---|---|
| `DATABASE_URL` (+ `DATABASE_URL_UNPOOLED`) or `OPS_DB_DSN` | Group database (Neon writes these with `neon deploy`) |
| `OPS_AGENT_KEY` | Fernet key that encrypts passport and ID numbers. Back it up |
| `OPS_FIREBASE_PROJECT`, `OPS_FIREBASE_WEB_CONFIG`, `OPS_ALLOWED_EMAILS`, `OPS_ALLOWED_DOMAINS` | Google sign-in for the hosted app (off when unset) |
| `OPS_OCR_THREADS` | Cap OCR threads (the hosted app uses 2 of 4 CPUs) |
| `OPS_FONT_CSS` | Web-font stylesheet URL |

## Hosting

Cloud Run service `ops-agent` (asia-southeast1) behind Firebase Hosting (`firebase.json`). `deploy.ps1` builds and deploys from source. Its settings file `deploy/env.yaml` holds secrets and is not in this repository.

Uploads are kept in memory per check, so the service runs a single instance. Long checks run in the background (`POST /api/groups/check?background=1`, then poll `GET /api/jobs/{id}`), because Firebase Hosting stops waiting after 60 seconds.

## Tests

```
pytest
```

This public repository only holds tests that use made-up data (`tests/fixtures/passport-specimen.png` is generated by `tests/make_passport_fixture.py`). The tests against real group files hold passport and ID numbers, so they stay in the team's private project folder (`tests/expected/` and `tests/private/` are git-ignored).

**Never commit customer files, `.env*`, or `deploy/env.yaml`.**
